# הוספת מתכון ללא שינוי HTML

1. פותחים ענף תוכן מתוך ענף המנוע המעודכן. מוסיפים רשומה ל־`data/recipes.json`, עם `id` מספרי חיובי חדש שלא נעשה בו שימוש (גם לא במפתח של `redirects`). אין למחזר מזהים של מתכונים שנמחקו. משמרים את שדות הקרדיט והמקור; הסכמה מפרטת את השדות הנדרשים. `photo` הוא מזהה מדיה קבוע, `scan` הוא מזהה סריקה או `null`, ו־`scanExtra` מכיל מזהי עמודי המשך.
2. לעבודה על המדיה משתמשים ב־worktree נפרד של `recipe-media`. שומרים תמונות כקבצים בינאריים, ללא Base64. מוסיפים נתיב חדש הכולל את מזהה המדיה וטביעת תוכן, למשל `media/photos/my-recipe--0123456789abcdef.avif`. אין להחליף קובץ של מתכון אחר או להשתמש בתמונת גיבוי של מתכון אחר.
3. מוסיפים למפת `photos` או `scans` ב־`data/media.json` רשומה תחת מזהה המדיה: `path` יחסי, `sha256` מלא ו־`bytes` (גודל הקובץ). לקבלת הטביעה והגודל אפשר להשתמש ב־Python: `hashlib.sha256(Path(path).read_bytes()).hexdigest()` ו־`Path(path).stat().st_size`.
4. מבצעים commit למדיה, ודוחפים אותו לענף המדיה לפני ענף התוכן. מעדכנים את `data/media-source.json` ל־SHA המלא של אותו commit. כך גם מתכון קיים יכול להפנות לתמונה חדשה בלי לשנות את מנוע האתר.
5. מעדכנים `metadata.total` למספר הרשומות. בקטגוריה קיימת אין צורך בשינוי HTML, CSS או JavaScript; מוני הקטגוריות נגזרים מהנתונים. קטגוריה חדשה דורשת גם בחירת אייקון ותמונת קטגוריה במנוע.
6. בונים ומריצים את בדיקות התקינות והדפדפן לפי README. בודקים גם את המתכון החדש, הקרדיט והתמונה מול המקור. מעלים ענף לביקורת לפני מיזוג ל־main.

המיגרציה משמרת את `#recipe-ID`, את 20 ההפניות הקיימות ואת מפתח המועדפים `my-recipe-favorites`. כאשר ממזגים מתכונים בעתיד, מוסיפים הפניה מ־ID ישן ל־ID קיים ולא משנים את משמעותו של ID קיים.

שגיאת JSON, מזהה כפול או הפניה למדיה לא קיימת עוצרים טעינת ספרייה ומציגים הודעת שגיאה. כשל HTTP של תמונה בודדת מסתיר רק את התמונה הכושלת; לא נעשה שימוש בתמונה חלופית שעלולה לשייך מנה אחרת. בדיקות הבנייה מוודאות שכל קובץ במדיה קיים ותואם לטביעתו ולגודלו.
